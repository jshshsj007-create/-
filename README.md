# نادي مدارس الأحياء — تطبيق الإدارة

تطبيق ويب لإدارة كيانين مستقلين:

1. **البرامج** — البرنامج الترفيهي المشترك بين فريق فيض ومدارس الرواد. تسجيل الطلاب، الحضور،
   المصروفات، ثم توزيع الصافي بين الطرفين.
2. **فيض** — رصيد الفريق وحساباته (الراجحي، أبو فارس، القاسم، كاش) بإيراداته ومصروفاته المستقلة.

بجانبهما: السفرات، والإعداد (المسابقات)، والمستخدمون والصلاحيات.

التصميم للجوال أولًا: شاشة بداية ← اختيار السنة ← اختيار الترم ← القائمة الرئيسية،
وشريط تنقل سفلي.

## التشغيل

```bash
npm install
npm run dev      # التطوير على http://localhost:5173
npm run build    # نسخة الإنتاج في مجلد dist/
npm run preview  # تجربة نسخة الإنتاج محليًا
npm test         # الاختبارات
```

## النشر

بعد `npm run build` يصير مجلد `dist/` جاهز للرفع على أي استضافة ملفات ثابتة
(Netlify أو Vercel أو GitHub Pages أو استضافة عادية). المسارات نسبية، فيشتغل من أي مجلد.

التطبيق **PWA**: يقدر أي أحد يفتح الرابط على جواله ويضيفه للشاشة الرئيسية، فينفتح
بملء الشاشة بأيقونة فيض بدون شريط المتصفح.

> تنبيه: الاستضافة توصّل التطبيق للناس، لكنها **ما تشارك البيانات بينهم** — راجع
> «الحفظ والتخزين» تحت. كل شخص يفتح الرابط تبدأ عنده نسخة فاضية على جهازه.

بنية المشروع:

```
index.html          صفحة التطبيق وبيانات الـ PWA
src/App.tsx         التطبيق كامل (المكوّن الرئيسي ودوال الحساب)
src/main.jsx        نقطة التشغيل
src/index.css       Tailwind وخط Tajawal
public/             الأيقونات وملف الـ manifest
tests/              اختبارات الحساب والصلاحيات
```

## الحفظ والتخزين

**الحفظ تلقائي** — ما فيه زر حفظ، كل تعديل ينحفظ فورًا ويظهر مؤشر «محفوظ» في الهيدر.

التخزين حاليًا عبر `window.storage` إن وُجد، وإلا `localStorage` — يعني **داخل متصفح كل شخص**.
ينبني على هذا:

- الرابط ما ينفع تعطيه لأحد ويشوف بياناتك؛ راح يفتح تطبيقًا فاضيًا عنده.
- المستخدمون والصلاحيات موجودون في جهازك أنت فقط.
- كلمة المرور تقسم الأدوار داخل الفريق، لكنها **ليست حماية** — الكود يشتغل بالمتصفح
  وأي شخص يفتح أدوات المطوّر يقدر يشوف البيانات ويتجاوزها.

عشان يصير رابط واحد يدخل عليه الجميع كل بحسابه وبيانات مشتركة ومحمية، لازم قاعدة بيانات
على سيرفر (مثل Supabase). كل التخزين معزول في كائن `storage` أعلى `App.tsx`، فالربط
يتم من مكان واحد.

## النسخ الاحتياطي

من الإعدادات ← «النسخ الاحتياطي»: **نسخ البيانات** (يشتغل في كل مكان) أو **تنزيل كملف**
(محجوب في بعض البيئات). الاسترجاع يقبل ملفًا أو نصًا ملصوقًا، ويتحقق من صحة النسخة
ويعرض محتواها (كم برنامج ويوم ومستخدم وعملية) قبل ما يستبدل أي شي.

خذ نسخة بعد كل برنامج تخلّصه — هي الشي الوحيد اللي يحمي بياناتك ما دام التخزين محليًا.

## الدخول والصلاحيات

الدخول باسم مستخدم وكلمة مرور. أول تشغيل بدون مستخدمين = وصول كامل بلا تسجيل دخول؛
أول ما تضيف مستخدم تظهر شاشة الدخول.

- دور «مدير» يملك كل الصلاحيات تلقائيًا.
- بقية الأدوار تُحدَّد لها الأقسام (البرامج، فيض، التقارير، النادي، …) ونطاق الأيام
  (كل الأيام أو أيام محددة). **الأقسام اللي ما له صلاحية فيها ما تظهر له أصلًا** —
  لا في الرئيسية ولا في الشريط السفلي.
- صاحب النطاق المحدود يشوف فقط البرامج اللي فيها أيام مسندة له، وتظهر له أيامه
  في الرئيسية تحت «أيامك» فيوصل لها بضغطة وحدة.
- المدير يقدر يعدّل بيانات أي مستخدم وصلاحياته، وتغيير كلمة المرور اختياري
  (يخليها فاضية تبقى القديمة).

## المعادلة المالية

هذي المعادلة الوحيدة اللي يشتغل عليها التطبيق كله:

```
الإيراد   = (مبلغ التسجيل السريع أو تحصيل المشاركين بالأسماء) + التحصيل الإضافي
الصافي    = الإيراد − مصروفات البرنامج
المتبقي   = الصافي − (نصيب مدارس الرواد + نصيب فريق فيض)
```

المصروفات تُخصم **قبل** التوزيع. نصيب كل طرف يُدخل يدويًا لكل أسبوع، والتطبيق يتحقق أن
المجموع يساوي الصافي:

| الحالة | ما يظهر |
|---|---|
| المتبقي = 0 | ✅ التوزيع مكتمل ومطابق |
| المتبقي > 0 | ⚠️ متبقي بدون توزيع + زر «أضف الباقي لنصيب فيض» |
| المتبقي < 0 | ⛔ التوزيع زائد عن الصافي |

## الربط بين البرامج وفيض

البرامج **لا** تمس رصيد فيض تلقائيًا. الربط يصير بخطوة واحدة صريحة:

زر **«ترحيل نصيب فيض إلى الرصيد»** في لوحة التوزيع → تختار الحساب (أو تقسّم المبلغ على
أكثر من حساب) → تُسجَّل عملية إيراد واحدة في فيض.

- الأسبوع المُرحّل يتعلّم بـ **مُرحّل لفيض**، وبنود نصيب فيض تُقفل عن التعديل.
- **إلغاء الترحيل** يحذف العملية من فيض ويرجّع الأسبوع لحالته الأولى.
- حذف العملية من صفحة فيض مباشرة يرجّع البرنامج كذلك لحالة «غير مُرحّل»، فما يصير تعارض.

## طريقتا التسجيل

لكل يوم وضع تسجيل:

**بالأسماء** (الافتراضي في كل البرامج) — كل طالب باسمه ومبلغه وطريقة دفعه
(الراجحي / أبو فارس / القاسم / كاش / ما دفع)، ومعه التحضير.
حالة اليوم تتحرك: **لم يبدأ ← جاري ← مكتمل**.

**سريع** (اختياري، للمنفصل فقط) — عدد الطلاب ومبلغ الإيراد بدون أسماء، لمن يبي تسجيلًا
مختصرًا ليوم ما يحتاج تحضير.

تقدر تحوّل أي يوم بين الوضعين من تبويب «نظرة عامة». المعادلة المالية وحدة في الحالتين؛
الفرق فقط في مصدر الإيراد وعدد الطلاب.

## أنواع البرامج

**منفصل (يوم واحد)** — كل يوم مستقل تمامًا: مشاركوه وحسابه المالي وتوزيعه وترحيله لفيض.

**مجمّع (أكثر من يوم)** — المشترك يُسجَّل **مرة واحدة** ويختار **الأيام اللي سجّل فيها**:

- يقدر يسجّل كل الأيام، أو يوم واحد بس، أو يجي اليوم الثالث ويسجّل من هناك.
- كل يوم يعرض **المسجّلين فيه فقط** عند تسجيل الحضور، وجنب كل اسم يبان حجم اشتراكه
  (مشترك يوم واحد / ٣ من ٤ أيام / كل الأيام) عشان المحضّر يعرف من قدامه.
- تقدر **تسجّل مشترك جديد من داخل صفحة اليوم** وأنت تحضّر — يُسجَّل في هذا اليوم وحده،
  وتقدر تزيد له أيام من نفس النافذة.
- نسبة حضور كل مشترك تُحسب من **أيامه هو**، مو من كل أيام البرنامج (اللي سجّل يوم وحضره = 1/1).
- الحساب المالي والتوزيع والترحيل على مستوى **البرنامج كله**، لا على كل يوم.
- تبويب «التقرير» يعرض مصفوفة مشترك × يوم، وفيها فرق واضح بين *ما سُجّل حضوره* (–)
  و*مو مسجّل في هذا اليوم أصلًا* (نقطة رمادية)، مع صف بعدد المسجّلين في كل يوم.

### سعر اليوم (اختياري)

لو حددت «سعر اليوم» للبرنامج المجمّع، يُقترح مبلغ كل مشترك تلقائيًا = عدد أيامه × السعر،
ويتحدّث كل ما تغيّر أيامه. أول ما تكتب المبلغ بنفسك، يوقف الاقتراح ويبقى رقمك.
لو ما حددت سعر، تدخل المبلغ يدويًا مثل قبل.

## الحسابات (الراجحي / أبو فارس / القاسم / كاش)

الحسابات مشتركة بين الكيانين، لكن بمعنيين مختلفين:

- **في فيض**: حسابات حقيقية، رصيد كل واحد = إيراداته − مصروفاته.
- **في البرامج**: تصنيف فقط (من وين استُلم المبلغ / من وين صُرف)، ما يغيّر أي رصيد
  إلا لما تضغط ترحيل.

الحساب المستخدم في أي عملية أو بند ما يُحذف — زر الحذف يختفي عنه.

## الاختبارات

```bash
./tests/run.sh
```

٣٩ اختبار يغطي:

- **المعادلة المالية**: خصم المصروفات قبل التوزيع، حالات المتبقي الثلاث، تجاهل «ما دفع».
- **التسجيل الجزئي**: المسجّلون في كل يوم، اللي جاء متأخر، نسبة الحضور من أيام المشترك،
  اقتراح المبلغ من سعر اليوم، وأن الغياب ما يشيل أحدًا من أيامه الباقية.
- **التسجيل السريع**: الإيراد والعدد، انطباق المعادلة نفسها، حالة اليوم المحسوبة،
  وترقية الأيام القديمة للوضع الصحيح.
- **الدخول والصلاحيات**: مطابقة اسم المستخدم، الحساب المعطّل، حصر الأقسام على صلاحيات
  المستخدم، نطاق الأيام المحدودة، تفرّد اسم المستخدم، وترقية المستخدمين القدامى.

تحتاج Node فقط (`esbuild` يُجلب عبر `npx` وقت التشغيل).
